# Contributing to DevBoard

Thank you for contributing to DevBoard for the Hack the Web event.

## Fork and clone

1. Fork the repository to your GitHub account.
2. Clone your fork locally.
3. Create a feature branch based on the issue you are solving.

## Branch naming

Use descriptive branch names such as:

- `fix/issue-1-form-validation`
- `fix/issue-2-responsive-layout`
- `fix/issue-5-local-persistence`

## Commit guidelines

- Keep commits focused and easy to review.
- Use clear, descriptive commit messages.
- Prefer one logical change per commit.

Good examples:

- `fix: add task title validation checks`
- `style: improve responsive task grid`
- `feat: add async loading state handling`

## Working on an issue

- Read the issue description before coding.
- Keep changes scoped to the issue.
- Avoid unrelated refactors or broad cleanup in the same PR.
- Validate the UI behavior before submission.

## Pull requests

- Open a pull request against the repository default branch.
- Reference the related issue number in the PR description.
- Include a short summary of the fix and testing performed.
- Keep the PR small and focused.

## Testing requirements

Before submitting a pull request:

- Open the app in a browser and confirm it loads.
- Check the affected screens and flows manually.
- Verify no JavaScript syntax errors are introduced.
- Ensure the fix does not break the rest of the dashboard.

## Event rule

PRs must be reviewed and merged to receive points for the event. Opening a PR alone does not qualify for points.
